10. Projeyi bitirecek gerçek sprint

Şimdi işi 7 ana faza bölelim.

FAZ 0 — Yeni PC başlangıç doğrulaması

Kod yazmadan önce bunu yapacağız.

VS Code terminal:

flutter doctor -v
flutter --version
dart --version

sonra:

flutter pub get
flutter analyze

ve Windows:

flutter run -d windows

Amaç:

Yeni PC'nin geliştirme ortamının gerçekten hazır olduğunu doğrulamak.

Bu aşamada problem çıkarsa önce onu çözeriz.

FAZ 1 — Veri katmanını tamamla

Bu en önemli faz.

Task SQLite

Yeni:

TaskTable
TaskPersonnelTable

kuracağız.

Neden iki tablo?

Çünkü:

Task
 ├── Personel A
 ├── Personel B
 └── Personel C

many-to-many ilişki.

Veritabanı:

tasks
task_personnel
personnel

olacak.

Sonra:

TaskRepositoryImpl

tamamen Drift kullanacak.

TaskLocalDatasource kaldırılacak.

Leave SQLite

Yeni:

LeaveTable

ve repository Drift'e geçecek.

Sonra:

LeaveLocalDatasource

gibi geçici yapı varsa kaldırılacak.

FAZ 2 — Uygulama genelinde veri tutarlılığı

Burada amaç:

Personel
Görev
İzin
Dashboard
Rapor

hepsinin aynı kalıcı kaynaktan beslenmesi.

Akış:

  ↓
Repository
  ↓

  ↓

olacak.

Bu faz bittikten sonra uygulama kapanıp açıldığında:

hiçbir görev veya izin kaybolmayacak.

Bu bizim ilk büyük “ürün artık gerçek” milestone'ımız.

12. Kodlama sıramız

Artık doğrudan şu sıradan gideceğiz:

1. Yeni PC / Flutter ortamını doğrula
2. Task → Drift
3. Leave → Drift
4. Task/Leave migration + test
5. Dashboard/Rapor/Detail yeniden doğrulama
6. Personnel getById + repository cleanup
7. History gerçek database
8. CRUD işlemlerine history olayları
9. HistoryTab gerçek veriye bağla
10. Dashboard son entegrasyon
11. Settings Data Management
12. Backup / Restore
13. Mock / geçici kod temizliği
14. flutter analyze
15. flutter test
16. Windows gerçek kullanım testi
17. Git release commit
En kritik karar

Burada Raporlar veya Ayarlar tarafında daha fazla özellik geliştirmeyeceğiz.

Raporlar yeterli.

Tema yeterli.

Ayarların mevcut temel yapısı yeterli.

Şimdi uygulamanın profesyonel şekilde bitmesini engelleyen esas şey verilerin kalıcı olmaması ve gerçek History altyapısının bulunmaması.

Dolayısıyla sıradaki gerçek kodlama:
Task → Drift/SQLite geçişi

Bu, bütün projenin en büyük kalan teknik işi.

İlk adımda TaskTable + TaskPersonnelTable + migration + mapper + repository'yi kuracağız; sonra mevcut TaskController'ı bozmadan aynı provider üzerinden devam edeceğiz. Böylece UI'ı yeniden yazmayacağız.
